# Bytecode VM runtime

**A from-scratch VM that reads a bytecode file and runs it on the emulated NPU (or, optionally, CUDA).** The design and internals live in [`doc/bytecode-vm-project.md`](../doc/bytecode-vm-project.md) and [`hal-design.md`](hal-design.md). This file is just how to build and run it.

## Build and run

All commands run from this folder (`runtime/bytecode-vm/`).

### Build

```
cmake -S . -B build      # generate the build files (run once, or after editing CMakeLists.txt)
cmake --build build      # compile
```

This builds two programs into `build/`:

| Program | What it does |
|---|---|
| `build/emunpu_test` | Runs the fixed two-layer network in `src/main_emunpu.cpp`. |
| `build/test_runner` | Runs any bytecode file you give it by path. |

The CUDA backend is off by default (this machine has no CUDA). To build it on a GPU machine:

```
cmake -S . -B build -DVM_ENABLE_CUDA=ON
cmake --build build
```

### Run one bytecode file

`test_runner` opens only the path you pass, so run it from here with the file's path — no need to move between folders:

```
./build/test_runner src/test-bytecode/tests/ok_minimal.txt
```

It prints one line: `PASS` / `FAIL`, the file name, and the real error message with its line. The verdict comes from the file name — a file named `err_*` must fail, `ok_*` must pass.

### Run the fixed demo program

```
cd src/test-bytecode && ../../build/emunpu_test
```

`emunpu_test` still hardcodes its bytecode filename, so it must run from the folder holding that file (`src/test-bytecode/`). `test_runner` does not have this limit.

### Run a whole test folder

The scripts find the built runner on their own, so call them from anywhere:

```
src/test-bytecode/tests/run_all.sh      # the normal test suite (53 files)
src/test-bytecode/stress/run_all.sh     # the stress / adversarial suite (26 files)
```

Each prints an aligned PASS/FAIL table. The noisy device logs go to a `detail.log` next to the script, so the summary stays readable. A `FAIL` on a stress "probe" test may be a real gap or a wrong name-guess — see that folder's `README.md`.

## Layout

```
runtime/bytecode-vm/
├── CMakeLists.txt          # the build recipe (commented; edit VM_SOURCES to add a file)
├── README.md               # this file
├── hal-design.md           # the Device (HAL) design
├── build/                  # generated by cmake -- not committed
└── src/
    ├── bytecode.{h,cpp}    # parser
    ├── vm_core.{h,cpp}     # the VM: dispatch loop, registers, control flow
    ├── io_handle.{h,cpp}   # host input/output slots
    ├── error.h             # Error type + RETURN_IF_ERROR macro
    ├── main_emunpu.cpp     # emunpu entry point (the demo program)
    ├── main.cpp            # CUDA entry point (built only with -DVM_ENABLE_CUDA=ON)
    ├── test_runner.cpp     # runs one bytecode file by path
    ├── hal/                # device backends: device.h, emunpu_device.*, cuda_device.*, kernels.*
    └── test-bytecode/
        ├── bytecode12*.txt # the demo programs
        ├── tests/          # normal test files + run_all.sh
        └── stress/         # stress / adversarial test files + run_all.sh
```
